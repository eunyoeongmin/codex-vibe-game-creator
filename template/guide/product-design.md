### 제품 설계 지원

사용자가 다음 항목을 정할 수 있도록 돕는다. 사용자가 이미 말한 내용과 저장된 결정을 바탕으로 아직 정하지 않은 항목을 다룬다.

세부 topic과 새 항목 추가 방법은 [제품 설계 category·topic 표](../catalogs/product-design-topics.md)를 기준으로 한다. 아래는 설계 영역의 개요이며, 사운드를 포함한 세부 선택 항목은 해당 표에서 고른다.

| 항목 | 결정할 내용 | 저장 category |
| --- | --- | --- |
| 핵심 루프 | 플레이어가 반복하는 행동 한 사이클. 예: 방 진입 → 전투 → 보상 선택. | `core_loop` |
| 플랫폼과 입력 방식·시점·UI | PC·모바일 등 대상 플랫폼, 키보드·터치 등 입력 방식, 시점과 UI를 선택하도록 돕는다. 다중 플랫폼을 원하면 각 플랫폼에 맞는 입력과 UI를 함께 정한다. | 플랫폼·입력은 `platform`에서 topic으로 구분하고, 시점은 `viewpoint`, UI 스타일은 `ui_style`, 색감은 `color_palette` |
| 범위와 분량 | 혼자 만드는지 등 제작 인원, 목표 플레이 시간, 스테이지 또는 콘텐츠 규모를 정한다. 수량 항목은 모호한 크기 표현 대신 단위와 정확한 수치를 가진 선택지를 제공한다. 예: 목표 플레이 시간 30분·60분·120분, 스테이지 6개·12개·24개. 게임에 맞는 단위와 수치로 후보를 제시하며, 스테이지가 없는 게임은 장면·이벤트 등 해당 콘텐츠 단위를 쓴다. | `scope` |
| 기술 스택과 에셋 제작 방식 | 원하는 엔진·언어와 에셋을 직접 제작할지, GPT image로 생성할지, 외부에서 가져올지 선택하도록 돕는다. 예: 마리오 같은 게임의 픽셀 아트를 JS/CSS 등 코드로 만들기, 이미지 생성으로 만들기, 가져온 에셋으로 만들기. 여러 방식을 원하면 에셋별로 사용할 방식을 구분해 함께 대응한다. | `tech_stack`; 화풍 자체는 `art_style` |
| 세계관과 톤 | 분위기 아래에서 스토리 필요 여부와 게임에 미치는 영향을 구체화한다. 스토리를 따라가는 것이 핵심인지, 수집 요소로 간접적으로 파악하는지, 내부 설정만 존재하고 플레이로 추측하게 하는지, 스토리가 필요 없는지 선택하도록 돕는다. | `mood` |
| 수익모델과 공개 계획 | 취미용인지 출시용인지, 공개 계획과 수익모델을 정하도록 돕는다. | `other` |

## 질문 진행 규칙

### 진행 안내 (기획 질문을 시작할 때 한 번)
기본 질문은 10개 안팎이고, 사용자가 언제든 "시작하자"고 하면 멈추며, 남은 항목은 AI가 제안으로 채운다고 한두 줄로 알린다. 질문이 아니라 안내이므로 답을 기다리지 않고 바로 첫 질문으로 넘어간다.

### 질문 묶음
- 장르와 핵심 루프처럼 게임 방향을 가르는 결정은 한 번에 하나씩 묻는다.
- 서로 이어지는 세부 항목(플랫폼·운영체제·화면 방향·시점, 화풍·분위기 등)은 AI가 한 세트로 제안하고 사용자가 승인하거나 일부만 수정하게 한다.
- 일부만 수정하면 수정한 항목은 새 값으로, 나머지는 그대로 confirmed로 저장한다.
- 저장은 항목별로 따로 한다.
- 레퍼런스나 이미 확정된 결정에서 답이 거의 정해지는 항목은 후보 없이 제안만 한다.
- 사용자가 답을 모르겠다고 하면 해당 질문의 후보를 제공한다.
- 사용자가 판단을 맡기면 AI가 선택한 안을 제안으로 제시하고, 같은 턴에 `status=proposed`, `ai_role=proposal`로 저장한다. 위임 자체를 해당 안의 확정으로 취급하지 않는다.
- 사용자가 여러 플랫폼이나 제작 방식을 원하면 하나로 임의 축소하지 않고 조합을 기록하고 대응한다.

### 체크포인트
- 현재 project_id의 confirmed 기록이 10건 쌓일 때마다(10, 20, …) 질문을 멈추고 /summary 내용을 보여준 뒤 묻는다: "지금까지 정한 내용이에요. 이제 시작할까요, 더 정할까요?"
- 시작을 고르면 아직 정하지 않은 항목은 AI가 제안안을 만들어 proposed로 저장하고, development.md의 개발 시작 절차로 넘어간다.
- 더 정하겠다고 하면 다음 체크포인트까지 이어서 질문한다.
- 사용자가 중간에 먼저 시작하자고 해도 같은 방식으로 처리한다.
- 참조: [development.md](development.md)

질문을 내는 방식(도구 사용)은 AGENTS.md의 "질문 방식"을 따른다.
