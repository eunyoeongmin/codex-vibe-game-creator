이 문서는 AGENTS.md의 일부이며, 규칙이 충돌하면 AGENTS.md를 따른다.

# 제작 도구

현재 맡은 작업에 해당하는 절만 읽는다. 이 문서의 도구를 사용하기 위해 다른 절까지 읽지 않는다. 아래 명령의 `decisions.py`는 AGENTS.md 실행 환경의 Python·스크립트 경로를 사용한다.

## 콘텐츠 편집

- 게임이 실제로 불러오는 JSON 객체 배열 또는 헤더가 있는 CSV만 등록한다. 편집용 복제 데이터를 별도로 두지 않는다. 코드에만 데이터가 있으면 승인된 작업 범위에서 파일로 분리하고 실제 로딩에 연결한 뒤 등록한다.
- 기존 ID를 유지한다. 필드 타입·필수 여부·수치 범위·선택지·참조 대상을 정하고 `decisions.py content register --input <정의 JSON 경로>`로 등록한다. 변경은 기존 revision을 `--revision`으로 전달한다. 정의 파일은 `.harness/`에 두어 게임 내보내기에 포함하지 않는다.
- 정의 형식: `id`, `name`, `path`, `id_field`, `fields`. 각 필드는 `key`, `label`, `type`, `editable`, `required`를 가진다. type은 string/integer/number/boolean/enum/reference, 수치는 min/max, enum은 options, reference는 대상 dataset ID를 사용한다. ID 필드는 string이며 수정할 수 없다. 자기 참조 외의 참조 대상은 먼저 등록한다.
- `decisions.py content list`, `content show <id>`로 등록된 정의와 현재 행을 조회한다. JSON/CSV는 2MB·3,000행 이하, 필드는 40개 이하를 지원한다. 배열·중첩 객체는 편집 필드로 등록하지 않는다.
- 사용자는 제작 도구에서 기존 행의 허용 필드를 바꾼다. 저장 시 타입·범위·ID 참조를 확인하며 다른 작업이 파일을 바꾸었으면 새로고침을 요구한다. 이전 파일과 변경 전후 값은 data/content-history/ 및 data/creator.sqlite에 남긴다.
- AI가 선택한 수치와 설계 근거는 기존 작업 결정 규칙을 따른다. 데이터 저장을 사용자의 게임 방향 승인으로 간주하지 않는다.

## 플레이 피드백

- 대시보드에서 화면을 캡처하거나 이미지를 첨부하고 사용자 설명과 함께 저장한다. AI에게 보내기는 별도 사용자 행동이다.
- 상태 제공을 요청받으면 게임에 `window.GameCreatorFeedback = () => ({...})` 함수를 연결한다. 현재 장면·플레이어 상태 등 요청에 필요한 JSON 값만 반환하며 게임 상태를 바꾸거나 개인정보를 수집하지 않는다. 함수가 없으면 화면·설명만 사용한다.
- 화면과 상태는 각각 수집 시각을 가진다. 수집되지 않은 상태를 관찰한 사실처럼 보고하지 않는다. `decisions.py feedback list / show <id>`로 원문·경로·상태를 조회한다.

## 체크포인트

- 사용자가 대시보드에서 저장·복원한다. 게임 파일·업로드/레퍼런스 파일·SPEC/STATE/ARCHITECTURE/마일스톤·결정 DB·콘텐츠 정의·스토리를 보관한다. 대화, 실행 환경, 지침, 다른 비교안은 되감지 않는다.
- 복원 전에 현재 상태를 자동 보관하고 교체되는 현재 파일을 discarded/에 둔다. 복원 후 AI는 이전 대화가 아닌 현재 파일과 기록을 기준으로 이어간다. 기존 대화와 파일이 달라졌다는 안내가 다음 요청에 포함된다.

## 비교안

- 사용자가 대시보드에서 이름·가설·HTML 진입 경로를 정하면 variants/<id>/에 게임 복사본을 만든다. `decisions.py variant list / show <id>`로 위치와 가설을 확인한다.
- 비교 요청을 맡은 담당은 전달받은 비교안 폴더 안의 게임 파일만 수정한다. 원본 게임·SPEC·확정 기록·마일스톤을 바꾸지 않는다. 작업 완료 후 비교할 행동과 실행 경로를 반환한다.
- 대시보드의 비교안 수정 요청은 해당 턴의 작업 디렉터리와 쓰기 허용 루트를 비교안 폴더로 지정한다. 원본의 지침은 필요한 절만 읽고 원본 DB에 기록하려고 권한을 우회하지 않는다.
- 원본과 비교안을 별도 루트로 실행한다. 채택은 사용자가 버튼으로 결정한다. 원본이 생성 당시와 달라졌으면 덮어쓰지 않고 거부한다. 새 비교안을 만들거나 차이를 먼저 조정한다.
- 채택 전에 원본 체크포인트를 만들고 이전 파일은 discarded/에 보관한다. 선택되지 않은 비교안은 그대로 남긴다.

## 스토리

- 스토리는 독립된 담당이 agents/story.md에 따라 작성한다. 게임 디자이너·개발·아트 작업에 이야기 작성을 섞지 않는다.
- `decisions.py story save --input <JSON 경로>`로 proposed 기록을 저장한다. 수정 시 기존 id와 `--revision`을 전달한다. 필수값은 kind(character/event/branch/world), title, body이며 condition, game_effect, links(스토리 ID 배열)를 함께 기록할 수 있다.
- `story list / show <id>`로 조회한다. AI 명령은 confirmed 저장을 거부하며 사용자는 스토리 화면에서 버전별로 확정한다. 변경 전후 버전과 작성 주체는 별도로 보존한다.
- 조건과 게임 영향은 설명 자료이며 자동 실행되지 않는다. 사용자가 적용을 요청하면 확정된 이야기와 게임 영향을 관련 담당에게 전달하고 기존 결정·마일스톤 절차에 따라 구현한다. 이야기 확정만으로 게임 기능을 추가하지 않는다.

## 게임 내보내기

- 사용자가 실행할 HTML 진입점과 이름을 골라 ZIP을 만든다. 루트 진입점이면 프로젝트 게임 파일, 하위 폴더 진입점이면 그 빌드 폴더를 내보낸다. 엔진 프로젝트는 먼저 웹 실행 결과를 빌드해야 한다.
- 지침·DB·숨김 파일·테스트·폐기 파일·비교안·미사용 등록 에셋은 제외한다. 선택한 빌드 폴더 밖의 파일에 의존하면 내보내기 전에 그 폴더 안에 배치하고 게임 참조도 함께 수정한다.
- ZIP에 실행 안내를 포함한다. HTTP 서버나 정적 호스팅으로 폴더 전체를 제공한다. 외부 URL 의존성은 포함된 파일이 아니며 온라인 연결이 필요하다. 내보내기 성공을 플레이 검증 성공으로 보고하지 않는다.
