# 작업 근거와 폐기 후보

두 절은 서로 독립적이다. 연결 관계를 조사하는 담당은 ‘기존 시스템 연결 조회’, 미선택 결과를 반환하거나 후보를 등록·조회하는 담당은 ‘폐기 후보’만 확인한다.

## 기존 시스템 연결 조회

구현·설계를 직접 수행하는 담당은 상태 변경·공통 처리·기능 간 호출을 연결하거나 바꿀 때 요청과 관련된 결정, 코드의 호출부와 공통 처리를 확인한다. 대시보드가 전달한 근거 후보를 시작점으로 사용한다. 필요하면 AGENTS.md의 Python·decisions.py 경로로 `context search "검색어"`를 실행하고 함수명·관련 용어로 좁혀 조회한다. 이 검색은 모델 없이 동작하는 제한된 키워드 검색이다. 검색 결과가 없다고 관련 시스템이 없다고 판단하지 않는다.

반환 결과에 재사용할 기존 동작, 영향받는 연결, 제외할 동작, 새 사용자 선택이 필요한 부분과 근거 ID·파일 위치를 포함한다. 이미 승인된 규칙과 위임된 범위 안의 제작 선택은 기존 작업 결정 규칙에 따라 기록한다. 단순히 기능 하나를 추가하기 위해 관련 없는 시스템을 바꾸거나 승인되지 않은 연출을 추가하지 않는다.

여러 기존 시스템을 이어야 해서 연결 설계가 필요한 요청은 guide/gameplay-tools.md의 ‘기존 시스템 연결 설계’ 절을 사용해 행동·상태 변화·기존 연결·남은 선택을 기록한다. 이미 확인한 근거를 재사용하고, 단순 수치·문구 수정에는 연결 설계 표를 새로 만들지 않는다.

## 폐기 후보

하위 담당은 미선택 정보·결과 파일의 경로와 이유·관련 기록 ID를 오케스트레이터에게 반환한다. 오케스트레이터는 실제 폐기 후보 파일만 `discard propose --path "assets/unused.png" --reason "선택되지 않은 후보" --record-ids A-001`로 등록한다. 목록은 `discard list`로 조회한다. 등록·조회 명령은 파일을 이동하거나 삭제하지 않는다.

사용자가 대시보드에서 후보를 선택해 `discarded/`로 이동하고, 이동한 파일의 최종 삭제도 직접 선택한다. 이동·삭제는 게임 코드나 에셋 기록의 경로를 자동으로 수정하지 않는다. 사용 중인 파일인지 확인할 근거를 후보의 이유와 관련 ID에 남긴다. 파일 내용이 등록 이후 달라졌다면 새 후보로 등록한다. 원래 파일이나 이동된 파일을 AI가 자동 정리하지 않는다.
